# よし、ニッチな技術をほそぼそと実装しよう

僕はふつうの社会人で、仕事は SIer をやっています。そんな僕が今、**仕事ではいっさい使わない**ニッチな技術 —— ゼロ知識証明の **Groth16** —— を、ほそぼそと勉強し、実装しています。

業務で使うわけでも、誰かに頼まれたわけでもありません。それでも「やりたい」と思ってしまったものは仕方ない。ずっと「実装したい」「記事にしたい」と思いつづけていたテーマでした。

とはいえ、なかなか踏み出せませんでした。そもそも勉強が追いついていないし、仕事も忙しく、体力と時間を捻出するのにも苦労する。おまけにプライベートでも大きな変化があって、正直てんてこ舞いでした。仕事に直結しない勉強なんて、後回しにする理由はいくらでもあります。

そんな状態でも「まあ、とりあえず書いてみるか」と思えたきっかけは、書店で[『技術書を書く技術』](https://www.shoeisha.co.jp/book/detail/9784798177045)を手に取り、購入したことでした。完璧な準備が整うのを待つのではなく、まず手を動かしてみる。この本に背中を押されて、ようやく一歩目を踏み出せました。

この記事では、そんな僕が、仕事に追われる日々のなかでどうやって**この「仕事では使わない勉強」のための時間を捻出しているか**、続けるなかで何を考えているか、そしてこれからどうしていきたいかを書き残しておきます。

題材はたまたま Groth16 ですが、ここに書く工夫のほとんどは、**仕事とは別に、何か学びたい・作りたいと思っているすべての社会人**に当てはまるはずです。資格でも、趣味の言語でも、自作キーボードでも、なんでもいい。「やりたいけど時間がない」「業務に関係ないし、いつかでいいか」と先延ばしにしている人が、読み終えたときに少しでも「自分もちょっとやってみようかな」と思えたら、この記事は大成功です。

## いちばん工夫したのは「時間の捻出」

特に工夫したのは、勉強と実装と執筆の時間をどう確保するか、でした。

前提として、僕の平日のスケジュールはだいたいこんな感じです。

| 時間 | やること |
| --- | --- |
| 7:00 - 8:00 | 通勤 |
| 8:00 - 13:00 | 仕事 |
| 13:00 - 14:00 | 昼休憩 |
| 14:00 - 20:00 | 仕事（早くて 19:00、遅いと 21:00 まで） |
| 20:00 - 21:00 | 帰路 |
| 21:00 - 22:00 | 夕食・風呂・掃除など |
| 22:00 - 6:00 | 睡眠（寝つきが悪いので実就寝は 23:00 くらい） |

見てのとおり、まとまった時間はほとんどありません。だからこそ、**スキマ時間に役割を割り振る**ことにしました。

### 勉強 —— 通勤の30分

まず、もともと英語で読んでいた以下の教材を、事前に Claude で日本語訳しておいて、それを読むことから始めました。

- [RareSkills の zk-book](https://rareskills.io/zk-book)
- [Groth16 のオリジナル論文](https://eprint.iacr.org/2016/260.pdf)

そして読みながら、不明点を Claude や Gemini に聞きつつ進めていきました。学習にあてたのは、主に**通勤の30分**です。

実装＆執筆を始めるまでの半年くらいで原文を読み、一部数式は写経もしてきたのですが、改めて日本語にすると理解がぐっと深まりました。そして同時に「生成 AI、すごすぎる」とも。翻訳はほぼ完璧だし、数式もちゃんと TeX で出力してくれる。**学習のハードルが一気に下がりました**。

### 実装 —— 昼休みと業後

実装は、**お昼休み**と**業務後**を使って進めました。

お昼はフードコートのカウンター席でうどんをすすり、そのあと 30〜40 分くらい、Claude と一緒にコーディング。この時間が地味に貴重で、いいリラックスタイムにもなっています。[Claude FM](https://share.google/MSIOAGsnQkYOPsbcf) を聞きながらやると、さらに「効きます」。

業務後は、19:00 に上がれた日はカフェに寄って、夕食も兼ねつつ作業。これも実装の時間にあてました。

### 執筆 —— 実装と同じ枠で

執筆も、基本は実装と同じ枠でやっています。手を動かして詰まったこと・腹落ちしたことを、そのまま記事のネタとしてメモしておく。実装と執筆を切り離さず、地続きにするのがコツでした。

## やりながら考えたこと

進めるなかで、いくつか自分なりの方針が固まってきました。

**数学はどうするか？** → 必要な分を、必要なだけ。
RareSkills いわく、Groth16 を理解するうえで重要なのは**群（group）の知識**だそうです。実際の計算は体（さらにいえば拡大体）の上で行いますが、体そのものを深掘りしなくても、群さえ理解できれば Groth16 は理解できる、と。楕円曲線も、群として捉えるとスッキリ腹落ちしました。なので、まずは群を軸に据えています。体論（？）や楕円曲線については深堀していません。

**Rust はどうするか？** → これも、必要な分を、必要なだけ。
言語としての基礎は、書籍でパラパラ眺める程度にとどめました。あとは Claude が出力したコードを見ながら、あれこれ質問して理解・納得し、自分の手で写経する。この進め方で、実装と並行して言語も身につけていきました。

**Groth16 以外もやる？** → やりません。まずは Groth16 を修める。
ブルース・リーの有名な言葉、

> 1万種類のキックを1回ずつ練習した相手は怖くない。だが、1種類のキックを1万回練習した相手は怖い。

これを地で行くつもりです。あれもこれもと手を広げず、まずは一つを深くやる。

### なぜ続けられているのか？

そして、自分でも意外なほど続けられている理由を振り返ってみました。

- **GitHub の streak を途切れさせたくない** —— 単純だけど、これが効く
- **ランチとセットにした** —— 習慣に紐づけると、やらざるを得なくなる。とはいえ眠すぎてサボる日もあって、そのくらいの緩さは許す
- **誰も見ていないし、期待もされていない** —— だから気楽に続けられる
- **生成 AI で実装イメージが湧きやすい** —— 一歩目のハードルが圧倒的に下がった
- **概念そのものが魅力的** —— だから「つまらない」と感じる瞬間がない
- **commit 単位を小さくする** —— 目に見える成果が積み上がっていく感覚がうれしい
- **仕事以外の居場所になっている** —— 一種の避難先として機能している
- **PC 一台で完結する** —— ハードウェアを触る題材だと、フードコートで広げるのも、毎日の通勤で持ち運ぶのもしんどい。その点これは身軽
- **ある程度成熟した言語で実装できる** —— Rust なら基本的な実行環境やクレートはもちろん、ゼロ知識証明を含む暗号ライブラリも、解説記事もそろっている。このあたりから自作となるとハードルはもっと高かったはず（今は Claude がいるので、案外なんとかなるのかもしれませんが）

特に「居場所になっている」点は大きくて、忙しいときほど、この時間が心の支えになっていました。

こうして並べてみると、続けるコツは Groth16 に限った話ではないなと気づきます。**①すでにある習慣にくっつける（ランチ＋実装）、②成果を小さく刻んで見えるようにする（小さな commit）、③サボる日を許す緩さを持つ。** この3つは、たぶん何を始めるときにも効くはずです。もし「続かない」と悩んでいるなら、ぜひ一つだけでも試してみてください。

## これからやりたいこと

Groth16 を一区切りつけたら、次はこのあたりに進んでいきたいと考えています。

- **zkVM**
- **TEE（Trusted Execution Environment）**

TEE に興味を持ったのは、[Acompany](https://acompany.tech/) のソリューションを知ったことがきっかけでした。SIer の端くれとして、「これ、現場の悩みをまるごと解決してくれるのでは？」と感じ、同時に「こんなことが本当にできるの？！」という驚きから、つまみ食い的に勉強を始めています。Intel SGX や TDX あたりの勉強会にも顔を出していきたいところです。

---

仕事に直結しない勉強は、いつだって後回しにできてしまいます。完璧な準備が整う日も、たぶん永遠に来ません。それでも「とりあえず始めてみるか」と踏み出してみたら、確かに何かが動き始めました。まとまった時間も、特別な才能も、強い意志も、実はそんなに要りませんでした。要ったのは、**通勤の30分とランチ後の40分、そして「とりあえず始める」という小さな決断**だけです。

もしあなたにも、仕事とは別に「いつかやりたい」と思っているものがあるなら、その「いつか」を今週のどこかに置いてみませんか。30分でいい。うまくいかなくてもいい。サボった日があってもいい。その一歩目が、思っているよりずっと遠くまで連れていってくれるはずです。

僕がそうだったように。あなたの「ほそぼそ始めたこと」の話も、いつかどこかで読めたらうれしいです。
