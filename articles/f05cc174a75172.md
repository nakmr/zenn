# なぜ多項式の演算を実装するのか？

Groth16 の核には、**「制約の集合（R1CS）を、多項式 1 本の等式で表す」** という変換 (QAP, Quadratic Arithmetic Program) にあります。
証明者は最終的に、$h(x) = (A(x) \cdot B(x) - C(x)) / Z(x)$ のような **多項式の割り算** を行って証明を構築しますし、検証者は **多項式の評価値（計算結果）が等しいか** だけで証明をチェックします。

つまり、Groth16 は「点で計算 → 多項式で検証」という考え方の上に乗っているのですが、そのためにはまず、有限体 $\mathbb{F}_p$ を係数とする多項式環 $\mathbb{F}_p[x]$ の上で、加減乗除と、特に **長除法** と **Lagrange 補間** が動く必要があります。

:::message
「環（ring）」とは「足し算と掛け算ができる集合」という代数の用語です。

- 整数 $\mathbb{Z}$ → 環（足せる、引ける、掛けられる。割り算は整数に閉じていない。）
- 有限体 $\mathbb{F}_p$ → 体（環であり、さらに 0 以外で割れる。）
- 多項式 $\mathbb{F}_p[x]$ → 環（足せる、引ける、掛けられる。割り算は一般に余りが出るので体ではない。）

つまり「多項式環」と呼ぶのは、**「多項式同士の割り算は割り切れない場合があるから、体ではなく環に留まる」** という代数的な分類を表しています。
:::

:::message
「長除法」とは、割り算の筆算のことです。ここでは、多項式版の筆算を実装することを意味します。
**「最高次の項同士を割る → 商の項を出す → 元の式から引く → 余りの次数を下げる」** ということを繰り返すアルゴリズムです。

たとえば $(x^2 + 3x + 2) \div (x + 1)$ なら:

```text
        x + 2
        ─────────
x + 1 ) x² + 3x + 2
        x² +  x
        ─────────
             2x + 2
             2x + 2
             ─────────
                  0    ← 余り
```

というように。
:::

:::message
今回は dense 表現（係数のベクタをそのまま持つ）で実装します。

- dense 表現
  - すべての次数の係数を、たとえ 0 でも順番に持つ
  - 例: `3 + 0x + 0x² + 5x³  →  [3, 0, 0, 5]   ← Vec の長さ = 次数 + 1`
- sparse 表現
  - 0 でない項だけを `(次数, 係数)` のペアで持つ
  - 例: `3 + 0x + 0x² + 5x³  →  [(0, 3), (3, 5)]   ← 0 の項は省略`

FFT による高速化やスパース表現は性能の話なので、学習段階では扱いません。型としても `Polynomial { coefficients: Vec<FieldElement> }` という素直な構造のみです。
:::

# 実装中の気づき

## dense 表現の末尾正規化と「全 0 のときは `[0]` を残す」

`coefficients[i]` を $x^i$ の係数とする dense 表現を採用しました。`[1, 2, 3]` なら $1 + 2x + 3x^2$ です。

このとき、`new()` で **末尾の 0 係数を落とす正規化** が必要になります。たとえば $1 + 2x$ を `[1, 2, 0, 0]` のように書かれてしまうと、`degree()` の値や同値判定がバラついてしまうからです。

最初は素直に「末尾が 0 ならひたすら `pop`」と書きましたが、これだと **全係数が 0 のときに `Vec` が空になってしまいます**。空っぽの vec になると `coefficients[0]` を触る `Sub`/`Mul`/`div_rem` や、素数 $p$ を取り出す `self.coefficients[0].p.clone()` などで、`index out of bounds` が発生してしまいます。

そこで、「**全 0 のときは `[0]` を 1 つだけ残す**」というルールを加えました。

```rust
pub fn new(mut coefficients: Vec<FieldElement>) -> Self {
    while coefficients.len() > 1 && coefficients.last().unwrap().value == BigInt::from(0) {
        coefficients.pop();
    }
    Polynomial { coefficients }
}
```

## `scale` を借用受けに直したら `.clone()` が消えた

スカラー倍メソッド `scale` を、最初は `scale(self, factor: FieldElement)` のように **所有受け** で書いていました。が、Lagrange 補間の中で `scale` を呼ぶたびに、呼び出し側で `factor.clone()` が必要になり、コードが汚くなる問題に気づきました。

そこで、`&self` と `&FieldElement` の **参照受け** に直しました。

```rust
pub fn scale(&self, factor: &FieldElement) -> Polynomial {
    let new_coeffs = self.coefficients.iter().map(|c| c * factor).collect();
    Polynomial::new(new_coeffs)
}
```

呼び出し側の `.clone()` がきれいに消え、Lagrange 補間の本体（後述）が読みやすくなりました。

前回も `Add<&'b FieldElement> for &'a FieldElement` のような **参照系トレイト実装** を採用しました。今回もそれと同じ思想で、Rust では **「迷ったら借用受け」** が良いデフォルトだと改めて感じています。

# 学んだこと

## なぜ多項式で「等しさ」を判定できるのか — Schwartz-Zippel の補題

### 解きたい問題

Groth16 の検証は、最終的に **「ある多項式の等式が成り立つか」** をチェックすることに帰着します。たとえば、

$$
A(x) \cdot B(x) = C(x) + h(x) \cdot Z(x)
$$

という等式が、 **すべての $x$ に対して** 成り立っているかを確かめます。

ここで困るのは、これらの多項式の **次数が回路の制約数オーダー** になることです。実用的な回路だと、次数が $2^{20}$ や $2^{30}$ になることも普通です。 **両辺の係数を 1 つずつ突き合わせる** ような愚直な比較をすると、それだけで膨大な計算量になり、「検証は軽い」というゼロ知識証明の利点が崩れてしまいます。

### 解決の発想:「1 点で評価して比べる」

そこで使う発想が、 **「両辺をある 1 点 $\tau$ で評価して値が一致すれば、多項式全体も等しいとみなす」** という方法です。
具体的には、

$$
A(\tau) \cdot B(\tau) \stackrel{?}{=} C(\tau) + h(\tau) \cdot Z(\tau)
$$

だけをチェックする。確認するのは **数値 1 つの等式** だけなので、検証はすぐに終わります。

ただ、ここで素朴な疑問が湧きます。

> 1 点で値が一致したからといって、本当に多項式全体が等しいと言えるのか？

意地悪な証明者が、 **ある $\tau$ では偶然一致するけど他の点ではバラバラ** な、偽の多項式を作ってきたらどうするのか。これに対する数学的な保証を与えてくれるのが、Schwartz-Zippel の補題です。

### 補題の心:「次数 $d$ の非ゼロ多項式は、根を高々 $d$ 個しか持てない」

Schwartz-Zippel の根っこにあるのは、高校でも触れる **代数学の基本的な事実** です。

> 次数 $d$ の非ゼロ多項式は、根（$f(r) = 0$ となる $r$）を高々 $d$ 個しか持てない。

例で確認すると:

- $f(x) = x^2 - 1$（次数 2）→ 根は $x = 1, -1$ の **2 個**
- $f(x) = x^3 - x$（次数 3）→ 根は $x = 0, 1, -1$ の **3 個**

「次数 $d$ → 根は高々 $d$ 個」が、多項式の **根本的な振る舞い** です。

これを「等しさ」の話に翻訳します。
$f(r) = g(r)$ という式は、移項すると $(f - g)(r) = 0$ と書けます。つまり $r$ は **多項式 $f - g$ の根** です。

ここで $f \ne g$ なら、多項式 $f - g$ は **非ゼロ多項式**（次数 $\le d$）、つまり、何らかの項をもちます。よって根は高々 $d$ 個。
**もし $r$ をランダムに選ぶなら、たまたまその $r$ が根に当たる確率は、サイズ $|S|$ の中の高々 $d$ 個 = $d / |S|$ 以下** ということになります。

これを正式に書いたのが、補題のステートメントです。

> 異なる $d$ 次以下多項式 $f, g \in \mathbb{F}_p[x]$ に対し、ランダムに選んだ $r \in S \subseteq \mathbb{F}_p$ で $f(r) = g(r)$ となる確率は高々 $d / |S|$ である。

ロジックを 3 行で表すなら:

1. $f \ne g$ なら $f - g$ は非ゼロ多項式（次数 $\le d$）
2. 非ゼロ多項式の根は高々 $d$ 個
3. ランダムに選んだ $r$ がたまたま根である確率は $d / |S|$ 以下

### BN254 での具体的な数字

「確率 $\le d / |S|$」だけだとピンと来ないので、Groth16 で使う BN254 の scalar field を当てはめてみます。

- $|S| \approx 2^{254}$（256 bit クラスの素数）
- 多項式の次数を仮に $d \approx 2^{30}$（10 億規模、かなり大きな回路）

このとき確率は

$$
\dfrac{d}{|S|} \approx \dfrac{2^{30}}{2^{254}} = 2^{-224}
$$

これは、暗号で「十分安全」とされる目安 $2^{-128}$ と比べても、さらに $2^{-96}$ 倍ほど小さい確率です。実用上はゼロとみなして問題ありません。

### 何が嬉しかったのか

整理すると、Schwartz-Zippel が保証するのは次のことです。

- 多項式を **係数ごとに比較** するのは重い
- でも、 **「ランダムに 1 点で評価して値を比較する」** で代用してよい
- 「悪意ある証明者が偶然 1 点だけ一致させる偽多項式を作る」確率は、暗号サイズの体ならほぼ $0$

つまり、 **重い「多項式の恒等性チェック」が、ただの「数値 1 個の等しさ」に圧縮できる**。これが、Groth16 の検証が定数時間で終わる根拠の 1 つです。

:::message

### 補足: Groth16 では $\tau$ をどう「ランダム」にするのか

「ランダムに $r$ を選ぶ」と言いましたが、実際の Groth16 では、検証者がランタイムで $\tau$ を選ぶわけではありません。 **Trusted Setup（「信頼できる」セットアップ）** で生成した **秘密の点 $\tau$** を、楕円曲線上の点に「焼き込んだ」もの（$g^{\tau}, g^{\tau^2}, \dots$）を CRS (Common Reference String) として使います。検証者はその CRS とペアリングを使って間接的に $A(\tau) \cdot B(\tau)$ を計算する、という流れです。

ただ、考え方の根っこは Schwartz-Zippel そのもので、**「証明者は $\tau$ を知らない → 1 点比較で十分」** というロジックは生きています。詳細は連載のもっと先の回で扱います。
:::

## 長除法の不変式 `self == divisor * quotient + remainder`

多項式の長除法は、高校で習う筆算とまったく同じです。

$$
f(x) = q(x) \cdot d(x) + r(x), \quad \deg r < \deg d
$$

この不変式は次の 2 つの主張をひとつにしたものです。

1. 商と余りは「足し戻すと元に戻る」
2. 余りの次数は除数より **厳密に** 小さい

実装中のループの読み方も、不変式に沿ってシンプルになります。

1. 余りの最高次を、除数の最高次で割って **商の最高次** を決める
2. 商 × 除数を作って **余りから引く** → 余りの次数が 1 つ下がる
3. 余りの次数が除数を下回るまで繰り返す

実装は次のようになります（メインループ部分のみ抜粋）。

```rust
while remainder.degree() >= divisor.degree()
    && !(remainder.coefficients.len() == 1
        && remainder.coefficients[0].value == BigInt::from(0))
{
    let deg_r = remainder.degree();
    let deg_d = divisor.degree();

    // a. 最高次の項同士の割り算（有限体なので逆元をかける）
    let leading_r = remainder.coefficients.last().unwrap();
    let leading_d = divisor.coefficients.last().unwrap();
    let ratio = leading_r.div(leading_d);

    let deg_diff = deg_r - deg_d;
    quotient_coeffs[deg_diff] = ratio.clone();

    // b. ratio * x^deg_diff * divisor を作って
    // c. 余りから引く
    // ...
    remainder = &remainder - &sub_poly;
}
```

ここでは、$0$ 多項式を除数として渡されたら `panic` させています。`Div` トレイトは `Option` を返せない都合で、`a / b` の構文の裏で `panic` になるしかない、という Rust 側の制約に従いました。

なぜここに紙幅を割くかというと、QAP では証明者が $h(x) = (A \cdot B - C) / Z(x)$ という割り算を実行します。 **ここで余りが 0 になることが、回路が「正しく満たされている」ことの証明そのもの** なのです。

## ホーナー法による評価

多項式 $P(x) = a_0 + a_1 x + a_2 x^2 + \dots + a_n x^n$ を $x = c$ で評価したいとき、素朴に書くと「各項で $a_i \cdot c^i$ を計算して足す」という発想になります。が、これだと $c^i$ を毎回計算することになり、項ごとに掛け算が積み上がって全体で $\mathcal{O}(n^2)$ です。

ホーナー法は、同じ式を **入れ子** で書き直します。

$$
P(x) = a_0 + x \bigl( a_1 + x \bigl( a_2 + x ( \dots + x \cdot a_n ) \bigr) \bigr)
$$

これを内側から計算すると、各ステップは「**前の結果に $x$ を掛けて、次の係数を足す**」だけになります。掛け算 1 回 + 足し算 1 回を $n$ 回繰り返すので、計算量は $\mathcal{O}(n)$。

実装は `evaluate` にそのまま落としています。

```rust
pub fn evaluate(&self, x: &FieldElement) -> FieldElement {
    let mut result = FieldElement::new(BigInt::from(0), x.p.clone());
    for coeff in self.coefficients.iter().rev() {
        result = &(&result * x) + coeff;
    }
    result
}
```

ポイントは `iter().rev()` で **最高次から回している** ことです。これで「内側 = 最高次 $a_n$」 → 「$x$ を掛けて $a_{n-1}$ を足す」 → ... というホーナーの入れ子をそのまま展開できます。

### なぜここで `coeff` は「足すだけ」でいいのか

最初に書いたとき、「多項式評価なんだから `coeff * 何か` を足すんじゃないの？」と一瞬手が止まりました。
ですが、ホーナー法では **$x$ を掛ける = 次数を 1 つ上げる**、 **係数を足す = その次数の項を導入する** と役割が綺麗に分かれます。なので、`coeff` 自体は掛けずに足すだけで済むのです。

実際、$P(x) = 1 + 2x$ で $x = 3$、$\mathbb{F}_7$ をトレースすると、こうなります。

| ステップ | coeff | result の更新 | result |
|---|---|---|---|
| 初期 | — | — | $0$ |
| 1 周目 | $2$ | $0 \cdot 3 + 2$ | $2$ |
| 2 周目 | $1$ | $2 \cdot 3 + 1$ | $7 \equiv 0$ |

最後の $7 \equiv 0$ が、そのまま $P(3)$ です。
前回の「繰り返し二乗法」と同じく、 **素朴な式を畳み直すだけで計算量のオーダーが落ちる** という、暗号実装で繰り返し出てくるパターンですね。

## Lagrange 補間 — n 点から n-1 次多項式を一意復元

n 個の異なる点 $(x_0, y_0), \dots, (x_{n-1}, y_{n-1})$ を通る多項式は、n-1 次以下の中に **一意に存在** します。それを書き下すのが Lagrange 補間です。

$$
P(x) = \sum_{i=0}^{n-1} y_i \cdot L_i(x), \qquad L_i(x) = \prod_{j \ne i} \frac{x - x_j}{x_i - x_j}
$$

肝になるのは基底多項式 $L_i(x)$ です。これは

- $x = x_i$ で **1**
- $x = x_j \,(j \ne i)$ で **0**

になるように作られた、いわば「$i$ 番目の点だけスイッチが入る」多項式です。これに $y_i$ を掛けて足し合わせれば、当然すべての $(x_i, y_i)$ を通ります。

### なぜ ZK で必要か

R1CS は「制約が n 個ある」表現です。これを QAP に変換する際、**n 個の制約を 1 本の多項式に圧縮する**ために Lagrange 補間が使われます。Groth16 の世界では、補間点として $x = 0, 1, 2, \dots, n-1$ を取るのが定番なようので、実装でもそれに合わせて固定しました。

```rust
pub fn lagrange_interpolation(y_values: &[FieldElement]) -> Polynomial {
    // ...
    for i in 0..num_points {
        let y_i = &y_values[i];
        if y_i.value == BigInt::from(0) { continue; }

        // L_i(x) の分子と分母を組み立てる
        let mut numerator = Polynomial::new(vec![FieldElement::new(BigInt::from(1), p.clone())]);
        let mut denominator = FieldElement::new(BigInt::from(1), p.clone());
        let xi = FieldElement::new(BigInt::from(i), p.clone());

        for j in 0..num_points {
            if i == j { continue; }
            let xj = FieldElement::new(BigInt::from(j), p.clone());

            // 分子に (x - xj) を掛ける（多項式 × 多項式）
            let term = Polynomial::new(vec![&zero - &xj, one.clone()]);
            numerator = &numerator * &term;

            // 分母に (xi - xj) を掛ける（スカラー × スカラー）
            denominator = &denominator * &(&xi - &xj);
        }

        let denom_inv = denominator
            .inverse()
            .expect("xi - xj is non-zero by construction (i != j)");
        let basis_poly = numerator.scale(&denom_inv);
        total_poly = &total_poly + &basis_poly.scale(y_i);
    }
    total_poly
}
```

実装中に一つ腹落ちしたのは、**分母 $(x_i - x_j)$ がゼロになる心配がない** ことです。 $i \ne j$ を構造的に保証している（`if i == j { continue; }` を書いている）ので、ここはどうやってもゼロになりません。`expect` のメッセージも、その理由がそのまま読めるように `"xi - xj is non-zero by construction (i != j)"` としました。未来の自分に「なぜ `expect` でいいのか」を説明するためのコメントです。

計算量は、各 $L_i$ の構築に $n-1$ 個の積、それを $n$ 回行うので $O(n^2)$ です。FFT を使った高速化は将来の話ということで、今回は素朴な実装を選びました。

# まとめ

- 多項式の **等しさ** は、Schwartz-Zippel によって **1 点の評価** に置き換えてよい
- 長除法の不変式 $f = q \cdot d + r$ が分かれば、QAP で出てくる $h(x) = (A \cdot B - C) / Z(x)$ も同様に考えればよい
- ホーナー法は「$x$ を掛ける + 係数を足す」を $n$ 回繰り返すだけで $O(n)$ 評価を実現する。素朴な $O(n^2)$ を畳み直す典型例
- Lagrange 補間は **n 個の制約 → 1 本の多項式** に畳む、ZK の常套手段
