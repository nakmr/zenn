# なぜ R1CS と QAP を実装するのか？

Groth16 の検証は、最終的に **「ペアリングで多項式の等式を 1 点の評価で確かめる」** という操作に集約されます。
そのためにはまず、証明したい計算、例えば「$x$ を秘密にしたまま $y = x^3 + x + 5$ を満たすことを示したい」などを、 **多項式の等式の形** で表現しておく必要があります。

ただ、いきなり計算を多項式にするのは飛躍が大きすぎます。そこで、間に **R1CS（Rank-1 Constraint System）** という中間表現を挟みます。流れにすると、

1. 計算を **R1CS の制約の集合** に分解する
2. 制約の集合を **QAP（Quadratic Arithmetic Program）** = **多項式の組**に畳む
3. 多項式の等式をペアリングで検証する（← 次回以降）

という三段構成です。
本章で実装するのは、このうち 1 と 2 にあたる部分です。前回作った Lagrange 補間もここで利用します。

:::message
- **R1CS = Rank-1 Constraint System**。「左辺どうしの積が右辺と等しい」を、**1 ステップにつき乗算 1 回** に正規化した制約形。詳しくは「学び 1」で。
- **QAP = Quadratic Arithmetic Program**。R1CS を多項式環 $\mathbb{F}_p[x]$ の世界で表現したもの。詳しくは「学び 2」で。
:::

# 実装中の気づき

## `CS_ONE = Variable(0)` という予約変数

最初に詰まったのは、「**定数加算 $a + 5$ を $A \cdot B = C$ の制約形にどう落とすのか？**」というところでした。

R1CS の制約 $A \cdot B = C$ における $A$、$B$、$C$ は、各変数の 係数つき和（線形和） $\sum_j \alpha_j x_j$ の形です。ここに「$5$ を足す」を素直に書こうとすると、$\alpha_j$ にも $x_j$ にも当てはまらない、定数項が出てきてしまいます。

解決策は、**インデックス 0 に「常に値 1 の変数」を予約しておく** ことです。これを `CS_ONE = Variable(0)` としましょう。値が常に $1$ なので、$5 = 5 \cdot \text{CS\_ONE}$ と書けます。つまり、定数項も「ふつうの線形和の項のひとつ」として扱えるようになります。

実装上は、制約系（Constraint System）を作った直後に `init_one()` を 1 回だけ呼んで `assignments[0] = 1` を入れるようにしています。

```rust
pub fn init_one(&mut self, one: FieldElement) {
    if self.assignments.is_empty() {
        self.alloc_variable(); // Index 0 を確保
    }
    self.assign(CS_ONE, one);
}
```

## ゲートが「制約追加」と「Witness 計算」を同時に行う

`mul(a, b)` のような **ゲート関数** をどう設計するかには、以下の選択肢がありました。

- 案 A: 「制約を追加する処理」と「値を計算して埋める処理」を 別々の関数に分ける
- 案 B: 1 つの `mul(a, b)` の中で、「新変数 `c` の確保 → `c = a * b` の値計算 → 制約 `(a)·(b) = (c)` の追加」をまとめてやる

最終的に案 B を採用しました。値計算と制約追加を分けると、「制約は通るのに値が違う」「値だけ正しくて制約が抜けている」といった不整合が起きやすく、デバッグもつらくなりそうだからです。

同時にやってしまえば、「Witness は必ず制約を満たす」ことを、このゲートで保証できます。Prover 側でいちいち整合性をチェックする必要もありません。

```rust
pub fn mul(&mut self, a: Variable, b: Variable) -> Variable {
    let c = self.alloc_variable();

    // 値の計算（Witness 生成）
    let val_a = self.assignments[a.0].as_ref().expect("variable a is unassigned");
    let val_b = self.assignments[b.0].as_ref().expect("variable b is unassigned");
    let val_c = val_a * val_b;
    self.assign(c, val_c);

    // 制約: (a) * (b) = (c)
    let mut lc_a = LinearCombination::new();
    lc_a.add_term(a, self.one());
    let mut lc_b = LinearCombination::new();
    lc_b.add_term(b, self.one());
    let mut lc_c = LinearCombination::new();
    lc_c.add_term(c, self.one());
    self.enforce(lc_a, lc_b, lc_c);

    c
}
```

# 学んだこと

## なぜ $A \cdot B = C$ という制約形なのか

R1CS の見た目は、よく考えると妙に制限的です: **「乗算 1 回 と 線形和」** だけ。
たとえば $w = x \cdot y \cdot z$ のような 3 つの積を、ひとつの制約に押し込むことはできません。代わりに、

$$
v_1 = x \cdot y, \quad w = v_1 \cdot z
$$

のように、乗算 1 個ずつの 2 制約に分解する必要があります。

なぜそんな縛りがあるのか？
理由は、Layer 3 で扱う **ペアリング** が「秘密の値 同士の 1 回の乗算」しか提供できないためです。

Groth16 では、秘密の値 $x$ を直接扱う代わりに $g^x$ という形に「隠して」計算を進めます。離散対数の仮定により、$g^x$ から $x$ を復元するのは事実上不可能で、$x$ を秘密にしたまま、群の要素である $g$ の肩の上で演算できる、というわけです。

加算は素直で、群の掛け算が、そのまま指数の足し算になります。

$$
g^a \cdot g^b = g^{a + b}
$$

つまり、$a, b$ を隠したまま **$a + b$ を計算できる**。公開値 $c$ とのスカラー倍 $(g^a)^c = g^{a c}$ も同様に計算できます。

問題は、秘密の値同士の **掛け算 $a \cdot b$** です。$g^a \cdot g^b$ では $g^{a + b}$ にしかならず、$g^{ab}$ は作れません。ここで登場するのがペアリング $e(\cdot, \cdot)$ で、

$$
e(g^a, g^b) = g_T^{ab}
$$

のように、積 $ab$ を、別の群 $G_T$ の要素 $g_T$ の指数に持ち上げて（lift）くれます。

ただし、結果は **元の群 $G$ ではなく、別の群 $G_T$** に飛んでいきます。そして $G_T$ には、さらに次のペアリング $G_T \times G_T \to \, ?$ がありません（※BN254 など標準的な設定だと、そうなっている）。だから、

$$
\underbrace{e(g^a, g^b)}_{= \, g_T^{ab}} \;\text{と}\; g^c \;\text{をもう一度ペアリングで噛み合わせて}\; g_T^{abc}
$$

を作る、というような連鎖はできません。これが「乗算 1 回しか提供できない」の正体です。

逆に言えば、**乗算 1 回までなら、$G_T$ 上の等式チェックに帰着できる**。そのために計算をあらかじめ「1 ステップにつき秘密の値同士の乗算 1 回」の単位にバラしておきたい。これが R1CS の $A \cdot B = C$ という形に対応します。

つまり、**R1CS は「ペアリングで検証できる形」から逆算した、計算の正規形** ということです。

具体例として、$y = x^3 + x + 5$ を R1CS に展開すると次のような流れになります。

1. $v_1 = x \cdot x$（乗算 1 回）
2. $v_2 = v_1 \cdot x$（乗算 1 回。ここで $x^3$ が出てくる）
3. $v_3 = v_2 + 5$（線形和、`add_const`）
4. $y = v_3 + x$（線形和、`add`）

乗算をひとつずつバラして、足し算は線形和に押し込んでいるのが見えると思います。
これが ZK の世界で言う **算術回路** の正規形で、 **「乗算ステップごとに 1 つの制約が立つ」** という構造になっています。

## 行列の「列」を Lagrange 補間して多項式に畳む

R1CS をそのまま並べると、3 つの行列（$A$、$B$、$C$）になります。サイズはどれも「制約数 $\times$ 変数の数」。
たとえば、制約 3 本、変数 4 個なら、$3 \times 4$ の行列が 3 つになります。

ここから QAP へ変換するアイデアは、**「行列の列ごとに、Lagrange 補間で 1 本の多項式を作る」** というものです。

- 変数 $j$ の A 列を取り出すと、$(A_{0,j}, A_{1,j}, \dots, A_{n-1,j})$ という $n$ 個の数値ベクトルになる
- これを **補間点 $x = 0, 1, \dots, n-1$ における $y$ 値** とみなして、前回作った Lagrange 補間にかける
- 結果として、変数 $j$ に対する多項式 $a_j(x)$ ができる

同じことを B 列・C 列でもやるので、各変数 $j$ ごとに 3 本の多項式の組 $(a_j(x), b_j(x), c_j(x))$ が得られます。

```rust
pub fn from_r1cs(cs: &ConstraintSystem) -> Self {
    let num_vars = cs.next_var_index;
    let num_constraints = cs.constraints.len();
    let p = /* assignments[0] から法 p を取り出す */;

    let interpolate_column = |matrix: Matrix| -> Vec<Polynomial> {
        (0..num_vars)
            .map(|i| {
                let points = extract_column(cs, i, matrix);
                let dense = to_dense_vector(points, num_constraints, &p);
                Polynomial::lagrange_interpolation(&dense)
            })
            .collect()
    };

    Qap {
        a_polys: interpolate_column(Matrix::A),
        b_polys: interpolate_column(Matrix::B),
        c_polys: interpolate_column(Matrix::C),
    }
}
```

なぜこれで「制約の集合」が表現できるのか?
カラクリは、**$x = i$ における多項式の値が、ちょうど制約 $i$ 番目の係数そのもの** になっていることです。Lagrange 補間は補間点で指定の $y$ 値を取るので、$a_j(i) = A_{i,j}$ になります。

つまり、「制約 $i$ 番目で変数 $j$ にかかっている係数」を知りたければ、多項式 $a_j(x)$ に $i$ を代入するだけでよい、という形に翻訳できたわけです。**行列の情報を、$n$ 本の多項式に圧縮できた** とも言えます。

## $h(x) \cdot Z(x)$:「全制約を満たす」を多項式の割り算で表す

QAP まで作れたら、Witness $s = (s_0, s_1, \dots, s_m)$ をかけて、各変数の多項式を足し合わせます:

$$
A_s(x) = \sum_j s_j \cdot a_j(x), \quad B_s(x) = \sum_j s_j \cdot b_j(x), \quad C_s(x) = \sum_j s_j \cdot c_j(x)
$$

すると、「Witness $s$ が全制約を満たす」という条件は、次のように書き換わります。

$$
A_s(x) \cdot B_s(x) - C_s(x) \text{ が } x = 0, 1, \dots, n-1 \text{ で } 0
$$

各 $x = i$ で 0 になる、というのは、（Lagrange）補間点 $i$ における **制約 $i$ 番目** がきちんと $A_i \cdot B_i = C_i$ を満たしている、ということと同じです。

これは記号がだいぶ圧縮されているので、ほどいておきます。さきほど作った $a_j(x)$ は、行列の列 $(A_{0,j}, A_{1,j}, \dots, A_{n-1,j})$ を補間点 $0, 1, \dots, n-1$ で Lagrange 補間したものでした。Lagrange の定義から、整数 $i$ を代入すると **行列の $(i, j)$ 成分そのもの** が出てきます:

$$
a_j(i) = A_{i,j}
$$

これに Witness $s = (s_0, s_1, \dots, s_m)$ を掛けた $A_s(x) = \sum_j s_j \cdot a_j(x)$ を $x = i$ で評価すると、

$$
A_s(i) \;=\; \sum_j s_j \cdot a_j(i) \;=\; \sum_j s_j \cdot A_{i,j} \;=\; \bigl(A\text{ の }i\text{ 行目}\bigr) \cdot s
$$

となり、**$A_s(i)$ は「制約 $i$ 番目における $A$ 側のスカラー値」そのもの** だと分かります。$B_s(i)$、$C_s(i)$ も同じ仕組みです。結果として、$A_s(i) \cdot B_s(i) - C_s(i) = 0$ は **「制約 $i$ 番目がきちんと満たされている」と全く同じ条件** になります。

::: details 簡単な例で確認

制約が $x \cdot x = v_1$ という 1 つだけで、Witness $(s_0, s_1, s_2) = (1, 3, 9)$（順に $\text{CS\_ONE}$, $x = 3$, $v_1 = 9$）のケース:

- $A$ の 0 行目: $(0, 1, 0)$ → $a_0(0) = 0, \; a_1(0) = 1, \; a_2(0) = 0$
- $A_s(0) = 1 \cdot 0 + 3 \cdot 1 + 9 \cdot 0 = 3$ → $x$ の現在値そのもの
- 同様に $B_s(0) = 3$, $C_s(0) = 9$
- $A_s(0) \cdot B_s(0) - C_s(0) = 3 \cdot 3 - 9 = 0$ → 制約満足 ✓

:::

そして、**「補間点全部で 0 になる多項式は、$Z(x) = \prod_i (x - i)$ で割り切れる」** が因数定理から言えます。したがって、

$$
A_s(x) \cdot B_s(x) - C_s(x) = h(x) \cdot Z(x)
$$

を満たす **多項式 $h(x)$ が存在** します。証明者が知っているのは、まさにこの $h(x)$ です（前回の長除法でこれを実際に計算します）。

検証側は、**ある秘密の点 $\tau$ で両辺の値が等しいか** をペアリングで確かめるだけです。Schwartz-Zippel の補題により、この検証は「多項式の恒等式が成り立つ」とほぼ同じ意味になる、という前回の話につながります。

ここまで来ると、**前回までの道具がきれいに繋がる** のが分かります。

- Lagrange 補間 → R1CS の各列を多項式に畳む
- 長除法 → $h(x) = (A_s(x) \cdot B_s(x) - C_s(x)) / Z(x)$ を実際に求める
- Schwartz-Zippel → 1 点評価で多項式の等式を検証してよい根拠

「制約の集合」が「ある多項式の割り算が割り切れる」というたった 1 本の条件に圧縮されるのです！Groth16 の世界観の核心部が、ようやく見えてきた感じがします。

:::message

### 補足: 「$G_T$ に飛んだ値を次の制約に渡したら、群が変わっていかない？」

過去に「ペアリングは秘密の値同士の乗算 1 回しか提供できない」と書きました。素直に考えると、「じゃあ 1 回ペアリングを取って $G_T$ に着地したあと、その値を次の制約の入力に使ったら、 $G_T \times G_1 \to \, ?$ で詰むのでは？制約を重ねるごとに群が変わっていってしまうのでは？」という疑問が湧きます。

答えは、実は「**そもそも制約ごとにペアリングを取らない**」です。n 個の制約は QAP によって **1 本の多項式の等式** に畳まれているので、検証側は

$$
e\bigl(g_1^{A_s(\tau)}, \, g_2^{B_s(\tau)}\bigr) \;\overset{?}{=}\; e\bigl(g_1^{C_s(\tau) + h(\tau) Z(\tau)}, \, g_2\bigr)
$$

のような **ペアリング 1 回の等式** で全制約をまとめて検証します。左辺も右辺も $G_T$ に着地し、そこで値が等しいことを判定して終わり。$G_T$ から先に進む必要がないので、群が連鎖して変わっていく問題は起きません。

つまり、R1CS の「乗算 1 回」縛りは、「全制約を 1 回のペアリングで済ませる」ための前提条件なのです。
:::

# まとめ

- R1CS の $A \cdot B = C$ という縛りは、**ペアリングが乗算 1 回しか提供できない** という Layer 3 の制約を逆算した形だった
- R1CS から QAP への変換は、**行列の「列」を Lagrange 補間する** という一手で、「制約の集合」を「多項式の組」に翻訳する操作だった
- $h(x) \cdot Z(x)$ の登場により、**「全制約を満たす」が「ある多項式の割り算が割り切れる」と等価** になり、検証は 1 点評価に集約される
