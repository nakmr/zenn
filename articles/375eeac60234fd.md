# なぜ有限体の演算を実装するのか？

Groth16 はペアリング (pairing) を使う zk-SNARK であるため、BN254 などのペアリングフレンドリー、つまり扱いやすい楕円曲線を使用します。
曲線の方程式 $y^2 = x^3 + ax + b$ は素数 $p$ を法とする有限体 $\mathbb{F}_p$ 上で定義されるので、点の加算やスカラー倍を計算するには $\mathbb{F}_p$ 上の四則演算、特に逆元が必要になります。

:::message
Groth16 では実は素数体が2つ出てきます。曲線が定義される base field $\mathbb{F}_p$（点の座標が住む場所）と、スカラー倍の指数が住む scalar field $\mathbb{F}_r$（QAPの係数や witness が住む場所）です。今回の FieldElement はどちらにも使えるよう、$p$ を引数で受け取る作りにしています。
:::

今回は必要最低限の内容に絞って、有限体の要素 `FieldElement` と、その演算を実装しました。

# 実装中の気づき

## Rust の `%` 演算子は負数で負を返す

Rust の % は余りを求める演算子であるため、負数を割ると結果がマイナスになります。

```rust
println!("{}", -15 % 7);
// -1
```

そこで、`FieldElement` の初期化時には、負の数を正の数に「引き戻す」処理を加えました。これにより、負数を使った場合でも、有限体 $\mathbb{F}_p$ の要素が得られるようになります。

```rust
pub fn new(value: impl Into<BigInt>, p: impl Into<BigInt>) -> Self {
    let value = value.into();
    let p = p.into();
    let normalized_value = ((value % &p) + &p) % &p; // <- ここで正の数に引き戻す
    FieldElement {
        value: normalized_value,
        p,
    }
}
```

## `Into<BigInt>` を使ってパースする

Groth16 で利用する曲線が扱う素数 `p` (base field) または `r` (scalar field) のサイズは、BN254の場合 254 bit と、`u128` を使っても、型レベルで物理的に収まりません。
また、乗算の中間値は最大で約 `2p` bit、つまり 508 bit になることから、やはり Rust 標準の型では収まりません。

そこで、`BigInt` を利用して、可変長で大きな桁数の数を扱えるようにしました。

:::message
`BigInt` は内部が `Vec<u32>` のヒープ可変長整数です。つまり、`new()` するたびに `Vec` のアロケーションが走ります。また、可変長なので、固定幅の `u64` と比べると、演算速度は遅いです。なので、本番実装では、`ark-ff` などを利用して、処理速度にも気を配るべきです。
が、今回は学習用ということで `BigInt` を利用します。
:::

ただ、`BigInt` をメソッドの引数で型宣言してしまうと、呼び出し側で、毎回 `BigInt::from(i)` と書かなければならず、手間です。

```rust
let value = BigInt::from(5); // <- めんどくさい
let p = BigInt::from(7); // <- これもめんどくさい
let fe = FieldElement::new(value, p);
```

そこで、Rust の `Into` Trait を使って、`FieldElement::new()` の中で `BigInt` に変換するようにします。

```rust
pub fn new(value: impl Into<BigInt>, p: impl Into<BigInt>) -> Self
```

このように宣言すると、「`BigInt` に変換可能な、なんらかの型を受け取る」ということを宣言できます。
これにより、`i32`, `u64` などをそのままこのメソッドに渡せるようになり、実装がスッキリします。

```rust
let fe = FieldElement::new(5, 7);
```

# 学んだこと

## フェルマーの小定理 vs 拡張ユークリッド法

有限体の計算のうち、割り算 を実現するために逆元 $a^{-1} \mod p$ を求める必要があります。
その方法には「フェルマーの小定理」と「拡張ユークリッド法」がありますが、アプローチが異なります。

### フェルマーの小定理

$p$ が素数で $\gcd(a, p) = 1$ のとき

$$
\begin{aligned}
& a^{p-1} \equiv 1 \pmod{p} \\
\Rightarrow{}& a \cdot a^{p-2} \equiv 1 \pmod{p} \\
\Rightarrow{}& a^{-1} \equiv a^{p-2} \pmod{p}
\end{aligned}
$$

つまり、$a$ を $p-2$ 乗するだけで逆元が得られ、実装がシンプルになります。

### 拡張ユークリッド法

$ax + py = \gcd(a, p) = 1$ を満たす $x$ と $y$ を求めると、$x \equiv a^{-1} \mod p$ となります。$\gcd$ を計算する過程で、逆元が算出できます。

### なぜ拡張ユークリッド法の方が速いのか

実装では、`BigInt::modinv` を利用していますが、これは拡張ユークリッド法の実装です。というのも、

- フェルマーの小定理
  - $a^{p-2}$ を求めるために、`BigInt` の全幅を使った乗算を $\mathcal{O}(\log p)$ 回行う
  - 例えば 256 bit なら、約 256回、256 bit 同士の掛け算が発生する
- 拡張ユークリッド法
  - 割り算と引き算を $\mathcal{O}(\log p)$ 回だけ行う
    - ゆえに、拡張ユークリッド法の方が速い
  - また、中間値もステップを重ねるごとに小さくなっていく

つまり、教科書的な「簡潔で美しい定理」と、「実装での合理的な選択」は必ずしも一致しない、ということです。

## 繰り返し二乗法

$a^n$ を計算する際、素朴にやると：

$$
a \times a \times ... \times a
$$

と、n-1 回の掛け算を行います。この計算量は $\mathcal{O}(n)$ となります。

繰り返し二乗法は、指数 $n$ を2進数として捉えて：

- $n$ が偶数ならば $a^n = (a^{\frac{n}{2}})^2$
- $n$ が奇数ならば $a^n = a \times a^{n-1}$

これで、$\mathcal{O}(\log n)$ 回の掛け算で済みます。

### これがなぜ強力なのか

暗号用途では、$n$ が 256 bit、つまり $n \approx 2^{256}$ となります。
素朴に計算する場合、$2^{256}$ 回の掛け算をすることになり、宇宙の年齢をかけても終わりません。
繰り返し二乗法を使えば、$\log_2 2^{256} = 256$ 回の掛け算で計算が完了し、1秒かからず終わります。

実装では `pow` メソッドにそのまま実装しています。

```rust
// 指数の最下位ビットが1（奇数）なら、現在の base を結果に掛ける
if &exp % &two != zero {
    res = &res * &base;
}
// base を二乗する（base = base^2）
base = &base * &base;
// 指数を半分にする（右シフト）
exp = &exp / &two;
```

## 平方根の $p \equiv 3 \mod 4$ の簡易公式

$a$ の平方根 $\sqrt{a} \mod p$ を求める際、整数の世界の平方根と違い、有限体では：

- そもそも平方根が存在するとは限らない
- 存在するときも、求め方が $p$ の形によって違う

### なぜこれで動くのか

1. フェルマーの小定理から $a^{p-1} \equiv 1$
2. 両辺を $\frac{1}{2}$乗して $a^{\frac{p-1}{2}} \equiv \pm 1$
3. $a$ が平方剰余なら $+1$ 側、つまり $a^{\frac{p-1}{2}} \equiv 1$
4. 両辺に $a$ を掛けて $a^{\frac{p+1}{2}} \equiv a$
    - ここで指数 $\frac{p+1}{2}$ が偶数であってほしいです。なぜなら $a^{2m} = (a^m)^2$ と書き換えて、$(なにか)^2 \equiv a$ という形、すなわち=平方根の定義に持ち込めるからです。
5. $\frac{p+1}{2}$ が偶数、すなわち $\frac{p+1}{4}$ が整数なら、左辺は $(a^{\frac{p+1}{4}})^2$ となる
6. $\frac{p+1}{4}$ が整数 $\Leftrightarrow$ $p \equiv 3 \mod 4$
    - 右は「$p$ を 4 で割った余りが 3」という意味であり、「$\frac{p+1}{4}$ が整数」ということは、4 で割り切れる、ということです。

## 3つの学びを通じて

「逆元 = フェルマーの小定理」「平方根 = 公式」と教科書では一行で済む話も、実装してみると「じゃあ実際にどう計算（可能に）するのか」が問題の中心であると感じます。

- 逆元は理論上 $a^{p-2}$ だが、実装では拡張ユークリッド法を選ぶ
- $a^{p-2}$ を可能にしているのが繰り返し二乗法
- 平方根も $p \equiv 3 \mod 4$ という制約で実装が一気に簡単になる

数学の世界では「計算できる」が前提になっている操作も、実装（特に暗号）の世界では「いかに現実的な時間で計算するか」が主役になっています。
