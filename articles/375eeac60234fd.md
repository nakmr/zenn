## 0. はじめに

- この章で何を作るか: `FieldElement` 構造体（`GF(p)` 上の元）
- 章のゴール（読了後にできるようになること）
  1. なぜ ZK で有限体が必要か を一言で説明できる
  2. `GF(p)` 上の四則演算を Rust の演算子オーバーロードで実装できる
  3. 逆元 を `BigInt::modinv`（拡張ユークリッド法）で計算できる
  4. 平方根 が `p ≡ 3 (mod 4)` のときだけ簡単に解けることを理解する
  5. 負の値の `%` の罠 を踏まずに正規化を書ける
- 動くコードへのリンク

## 1. なぜ有限体が必要か

- ZK で使う多項式・楕円曲線・ペアリングはすべて $\mathbb{F}_p$ 上で定義される
- 浮動小数点も整数オーバーフローも怖くない理由（mod p で閉じている）
- 暗号で「逆元が存在する」必要があり、そのため `p` は素数（→ 体になる）
- BN254 のスカラー体の位数を実際に表示（`0x30644...`）
- 図: Groth16 の Layer 図（field がどこにあるか） / mermaid

## 2. 構造体と正規化

- `FieldElement { value, p }` の定義
- なぜ `BigInt` か（256bit を超える数を扱うため）
- **罠コーナー: Rust の `%` は負数で負を返す**
  - `(-1) % 7 == -1` の例
  - 解決: `((value % p) + p) % p`
- `new()` のコード提示（`impl Into<BigInt>` 版）
- 補足コラム: 「`Into<BigInt>` を使う理由」（API ergonomics）

## 3. 加減乗の演算子オーバーロード

- Rust の `Add` / `Sub` / `Mul` trait の説明
- `Add<&'b FieldElement> for &'a FieldElement` の選択理由
  - なぜ `&` 参照で受けるか（`BigInt` のクローン回避）
  - lifetime `'a, 'b` の意味
- 異なる `p` を渡したら `assert_eq!` で panic させる設計
- コード全文: `Add` のみ全表示、`Sub` / `Mul` は同型なので省略言及

## 4. 逆元と除法

- 数学: フェルマーの小定理 vs 拡張ユークリッド法
  - フェルマー: $a^{p-2} \bmod p$ で逆元（`pow` で書ける）
  - 拡張ユークリッド: より速い／`BigInt::modinv` が提供
- なぜ `modinv` を選んだか（性能 + 標準クレートに乗れる）
- **`Option<Self>` を返す設計の話**（0 のとき `None`）
  - 過去の `expect` 版との比較
  - 呼び出し側に責任を委譲する利点
- 除法 `/` は `a * b.inverse()` の糖衣
- 補足コラム: 「`Div` trait は `Option` を返せない」

## 5. べき乗：繰り返し二乗法

- 素朴な `for _ in 0..n { res *= base }` の問題（`O(n)`、指数が 256bit だと宇宙の年齢）
- Square-and-Multiply の図解（指数を2進数で見る）
  - 例: $a^{13} = a^8 \cdot a^4 \cdot a^1$（`13 = 1101₂`）
- コード（`pow` メソッド全文）
- 計算量 $O(\log n)$ の実感（256bit でも 256 回ループ）

## 6. 平方根：`p ≡ 3 (mod 4)` の簡易公式

- 数学: なぜ $(p+1)/4$ 乗で OK か（フェルマーの小定理から導出）
  - 軽い証明スケッチ（1〜2行）
- 平方剰余・非剰余の概念（簡単に）
- 検算 (`root^2 == self`) で平方剰余かを判定する仕組み
- BN254 のスカラー体は $p \equiv 1 \pmod 4$ なので Tonelli-Shanks が必要、と告知
- **Tonelli-Shanks への展望**（v1.x で実装予定、と示しつつ読者に「やってみよう」と振る）

## 7. テストで仕様を固める

- Rust の `#[cfg(test)]` の説明
- 書いたテストの一部を引用（3〜4件）
  - 負の値の正規化
  - フェルマーの小定理 ($a^{p-1} \equiv 1$) でべき乗を検証する手法
  - `should_panic` で異標数の panic を検証
  - `inverse(0) == None`
- テストを書いたら見えてきた「仕様の曖昧さ」
